让 AI 帮我打了一次算法比赛

一个小白，如何从陌生资料走到第一次可验证提交。

尔玉 · 2026.07.18

AI WORKFLOW / CASE 01
先走通一次，
再谈怎么变好。
01 / 小白视角

我只是想让 AI
帮我参加一次比赛

起点不是一套代码，而是一篇让我觉得有意思的文章。

资料 → 报名 → 环境 → 训练 → 提交
背景
我看到一篇算法竞赛文章

有兴趣，但不知道从哪里开始。

请求
让 WorkBuddy 负责推进

报名、配环境、整理数据、写代码、训练、第一次提交。

难点
真正难的是整条链路

不是记住一条命令，而是让每一步都留下证据。

02 / 先把名词讲成人话

YOLO：
在图片里找东西

左边是比赛原图，右边是这次训练出的模型真实跑出来的结果。

输入
一张课堂图片

图片里同时有听讲、站立等多人行为。

输出
框 + 行为 + 置信度

模型判断谁在做什么，以及它有多确定。

03 / WorkBuddy 赛题总结

它先把比赛
讲清楚

圈 1
不是 Kaggle 官方赛

是 2026 科大讯飞 AI 开发者大赛的算法赛题。

圈 2
四类课堂行为

handup · write · listen · stand。

圈 3
数据与交付

414 张训练、200 张测试；mAP@0.5；提交 200 个 txt。

04 / 人与 Agent 的边界

报名可以辅助，
账号承诺不能代替人

先卡在账号登录；登录完成后，又卡在参赛协议。WorkBuddy 没有假装完成，而是在身份和承诺两个节点明确停手。

人确认 · Agent 继续 · 全程留证
全过程归档：从报名到第一次提交 ↗
05 / 工程骨架

WorkBuddy 先搭了一副
项目骨架

先固定东西放在哪里，再谈模型效果。

docs/ 规则、合规、实验记录 classroom_behavior_detection/ 训练、推理、打包 data/ raw / processed / test weights/ yolov8n / s / m outputs/ 日志、图表、submit.zip
06 / 第一次提交

第一次提交，
先把流程跑通

第一次最容易碰到的不是“分数不够高”，而是文件格式不对、提交失败，或者本地和线上结果不一样。

0.51506第一次有效提交
→
0优化版评测失败
→
0.79856修复后线上分数
07 / 做都做了

要不再试试，
能不能把分数搞高一点？

从这里开始，我不再让 AI 盲目重跑，而是让每次修改都回答一个具体问题。

08 / 先别急着调参

先把每次实验
记清楚

不然跑了十次，只会剩下一堆模型，不知道哪次为什么更好。

09 / 九轮实验

做完第一次提交，
我又试了九轮

不是同时乱改一堆参数，而是每一轮只改一个主要变量，再看结果值不值得保留。

用了什么YOLOv8m + 同一套数据
做了什么比较输入尺寸、学习率、增强方式和验证方法
结果怎样留下更稳定的方案：单折峰值 0.93416，五折均值 0.91682 ± 0.02031
10 / 先看证据

指标要回到
训练产物里

单折峰值、五折验证和线上分数，回答的是三个不同问题。

0.93416
单折峰值
0.91682
五折均值 ± 0.02031
0.79856
修复后线上反馈
11 / 最有价值的一轮

一次失败，教会 AI 以后怎么检查

test_111.txt 第 18 行：height → 0.000000
旧校验器把 0 错误地当成合法值。

问题不是“这次手动删掉一行”就结束，而是让以后每一次提交都不会再带着同类错误。

1个高度为 0 的退化框 · 3498 → 3497
生成时：直接跳过退化框
打包时：强制检查宽高必须大于 0
以后再跑：用回归测试自动拦住同类问题
12 / 可以直接复制

给 Agent 一张
清楚的任务单

不用先懂所有技术，但要说清楚做到哪里、怎么证明、什么时候必须停下来问你。

“先帮我走到一次有效提交。每一步记录证据；遇到登录、协议或危险操作先停手；失败时告诉我原因和下一步。”
13 / 不只适用于比赛

下一次遇到
陌生任务，也能用

整理资料、分析数据、生产内容、跑自动化，本质上都要把“想做”变成“有结果、有证据”。

陌生任务 → Agent 执行 → 人来判断 → 结果回写
14 / 收束

AI 没替代算法，
它让小白走完了链路

边界
证据
判断
回写

先让 Agent 带你完成一次，再让结果告诉你下一步。
