# 桌面真实物件照片与建模接入说明

## 这份说明解决什么

以后要把真实键盘、机箱、鼠标、台灯或桌面摆件放进个人主页时，不需要重新描述整套页面。一次只选一个物件，按这里准备照片，AI 会生成候选模型并通过独立地址交付验收。

当前默认桌面不会因为收到照片自动变化。只有候选通过本地预览并由尔玉确认后，才会切换默认视觉。

## 原始照片放在哪里

- 原始照片默认只作为当前建模任务的输入，不放进公开 GitHub 仓库。
- 公开仓库只保存经过确认的 GLB、脱敏后的来源说明和必要的低分辨率参考图。
- 照片中如有屏幕内容、二维码、序列号、快递单、门牌、聊天记录或他人面孔，提交前先遮挡。
- 镜面机箱、屏幕和亮面键帽要检查倒影，避免把房间、人物或其他屏幕内容带进去。

## 通用拍摄方法

同一个物件使用相同光线和背景，尽量不要开人像虚化、滤镜或超广角畸变。

必拍：

1. 正面约 45 度。
2. 背面约 45 度。
3. 正上方。
4. 左侧和右侧。
5. 能看清接口、按键、标志和材质的局部细节。
6. 一张带尺子或已知尺寸物体的比例参考图。
7. 物件长、宽、高的实际数值，单位使用毫米。

拍摄时让完整物件都在画面内，四周留边；相机尽量与物件中部齐平。模糊、强反光或被手遮挡的照片可以补拍，不需要为了数量保留。

## 各物件额外要求

### 键盘

- 键盘正上方整图，确保每一排键帽都可辨认。
- 正前方低角度，用于确认键帽高度和外壳坡度。
- 左后方、右后方和底部。
- 旋钮、状态灯、接口、脚撑、品牌标志和特殊键帽近照。
- 键盘总长、总宽、前后高度；如有掌托，单独测量。

键盘是收到合格照片后的第一优先对象。它最靠近前景，真实比例和键帽细节对整体质感影响最大。

### 机箱

- 正面、左右侧板、背板和顶部。
- 玻璃侧板内的主要硬件布局；如不希望公开内部硬件，可只做外壳。
- 电源键、前置接口、散热孔、脚垫和灯光区域近照。
- 机箱长、宽、高，以及桌面上相对主显示器的位置。

### 鼠标

- 正上方、左右侧面、前端、尾部和底部。
- 滚轮、侧键、灯带、握持凹槽和标志近照。
- 总长、最宽处和最高点。

仓库里已有一只通用游戏鼠标 GLB，只用于验证管线，不代表尔玉实际使用的型号。真实照片到位后可以作为新的候选，不直接覆盖它。

### 台灯与摆件

- 关闭灯光拍一组，打开灯光再拍一组。
- 灯罩、底座、转轴和电线出口分别拍清楚。
- 摆件如有正反面图案，分别提供平视近照。

## AI 收到照片后的固定流程

1. 先检查照片完整度和隐私，不够时只列缺少的角度。
2. 为当前物件建立独立工作树和候选 id。
3. 使用图片转 3D 工具生成 2 至 3 个候选，或在 Blender 中手工补齐结构。
4. 统一 Y 轴向上、正面方向、原点、尺寸和场景缩放。
5. 清理隐藏几何、重复材质、无用动画和过大纹理。
6. 把来源、生成工具、输入素材权利和授权写入 `manifest.json`。
7. 运行 `npm run check:models` 和完整 `npm run verify:release`。
8. 只通过显式查询参数展示候选，同时保留程序化物件。
9. 生成默认版与候选版截图，交给尔玉确认。
10. 确认后再单独提交“设为默认”，并保留前一版本标签。

## 怎样发起下一次修改

可以直接说：

> 给个人主页的键盘做真实模型候选。这些是照片和尺寸；原始照片不要放到公开仓库。先检查素材是否够，再按 V0.9 模型接入 Gate 做一版独立预览。

如果只想往桌面增加小摆件，也需要说明希望放在什么位置、是否能点击、点击后展示什么内容。建模和交互仍分成两个可回退提交。

## 验收重点

- 第一眼是否像真实物件，而不是通用素材。
- 大小、朝向、悬空和接触阴影是否符合现实。
- 默认页面是否仍能快速打开，模型失败时是否自动回退。
- 点击、拖动和光标同步是否与旧版本一致。
- 模型来源、授权和照片公开边界是否写清楚。

没有通过以上检查的候选可以删除或留在独立分支，不进入默认页面。
