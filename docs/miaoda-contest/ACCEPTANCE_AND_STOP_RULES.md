# 验收与止损规则｜秒哒参赛版

## 1. 首轮验收顺序

先看画面，再看交互，最后才看文字细节。首轮不以“功能数量”取胜。

在进入本页的整场景验收前，img2threejs 生成的单个物件必须先完成独立模型验收。未达到 `90` 分的物件源码不得接入秒哒。

### 构图门：必须全部满足

- 画面是一张紧凑的个人桌面，而不是普通页面套桌面插画。
- 中间主屏在第一眼可见范围内足够大，能阅读标题与介绍。
- 左侧机箱、竖向副屏、中央主屏、桌垫上的键盘鼠标、台灯、两块分开的洞洞板都在画面中。
- 副屏是朝使用者微转的竖屏；右侧大洞洞板沿桌子右侧边线斜放，不贴在后墙，也不与小洞洞板叠放。
- 键盘、鼠标都位于同一张浅色桌垫上，底部没有显眼的大块空白。
- 没有 HUD、蓝紫科技风、终端、AR、底部黑条、营销型大标题或无关桌面杂物。

### 交互门：必须满足前三项

1. 点击副屏入口后，主屏会在显示器内部切换内容。
2. 有明确的主屏内返回主页入口。
3. 实体鼠标可在桌垫范围拖动，主屏光标同步移动。
4. 便利贴与至少一个徽章可点击并给出短反馈。
5. 键盘有轻量视觉反馈。

第 4、5 项可作为首轮缺口记录，不因它们牺牲前 3 项。

### Three.js 物件门：接入一个物件时必须全部满足

- 物件使用独立 TypeScript 工厂返回 `THREE.Group`，不携带页面路由和桌面世界坐标。
- 复杂模型网格不直接作为拖动命中区域；交互使用独立透明代理。
- 物件的生成源码、参考图、规格和对照截图可追溯。
- 物件替换不能改变原有拖动范围、主屏光标映射或其他桌面物件的位置。
- 几何体、材质和纹理在页面卸载时能够释放。

### 内容与安全门：必须全部满足

- 所有可见内容使用已确认的品牌、简介与占位；没有虚构经历、数据、奖项、客户或合作信息。
- 无服务器信息、密钥、私有路径和内部项目资料。
- 主屏无乱码、无无意义英文提示、无解释设计意图的元文案。

## 2. 止损规则

首轮只触发一次完整生成。

以下任一情况出现时，立即停止在秒哒内反复生成，不继续消耗秒点：

- 生成的是卡片式网页、工作台、营销落地页或全屏信息面板。
- 主屏过小，或桌面构图与批准图明显脱节。
- 把参考图直接铺成背景，或几乎没有独立物件与真实互动。
- 右侧洞洞板、副屏角度、键鼠与桌垫关系等核心空间关系明显错误。
- 为了修复构图而引入不在范围内的复杂功能。

停止后只做三件事：保存预览截图、记录与本规则的具体差异、回到文字提示词和参考资产清单修订。用户确认修订后，才允许下一次生成。

## 3. 修改优先级

每一轮只处理一个层级，顺序不可颠倒：

1. 构图和主屏阅读面积。
2. 物件位置、角度、比例与桌面关系。
3. 材质、键盘鼠标、洞洞板与品牌细节。
4. 副屏切换、鼠标同步和轻量彩蛋。
5. 正式内容、飞书链接和后续数据填充。

## 4. 比赛提交前检查

- 项目是在秒哒新建并完成，不依赖本地 Astro 项目运行。
- 有可公开访问的秒哒应用链接，且使用未登录访问测试过。
- 记录比赛所需的项目介绍、截图与公开链接。
- 比赛规则、截止日期和发布专区在提交当天重新以官方页面为准核对，避免使用过期信息。
