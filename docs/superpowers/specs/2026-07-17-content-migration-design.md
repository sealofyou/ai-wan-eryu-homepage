# AI玩尔玉个人主页内容迁移设计

## 结论

个人主页采用“少量精选、持续补充”的内容策略，不批量迁移旧博客，也不把飞书、`E:\workspace\article` 或 OSS 直接当成线上内容库。

站点中的 Markdown 是经过公开边界检查、重新整理后的发布快照。飞书、本地文章目录和 OSS 只作为来源；线上构建不依赖这些私有系统。

第一阶段优先处理文章，作品集和时间笔记继续按事件逐条增加，关于与合作保持最小内容。

## 已确认的信息结构

- `文章`：已经形成完整观点、教程或复盘的内容。
- `时间笔记`：记录一次分享、活动、项目节点或阶段变化，强调发生了什么。
- `作品集`：有明确问题、过程、产物和证据的项目，不用文章数量填充。
- `关于`：只保留稳定定位和必要入口，不提前补商业合作话术。

一次活动可以同时产生一条时间笔记和一篇文章，但两者不重复：

- 时间笔记写时间、场景、主题、现场材料和后续更新。
- 文章提炼活动中的一个完整判断，让没有参加活动的人也能独立阅读。

## 方案选择

### 方案 A：运行时读取飞书或 OSS

优点是内容更新集中，缺点是构建依赖认证、接口稳定性和私有资源权限，也容易误公开内部文档。当前不采用。

### 方案 B：批量同步所有历史内容

优点是页面很快变满，缺点是大量旧内容与现在的定位不一致，算法笔记、内部记录和重复草稿会显著降低主页质量。当前不采用。

### 方案 C：来源发现 + 人工边界 + Markdown 发布快照

这是当前采用的方案。AI 负责盘点、抽取、改写、查重和敏感信息扫描；最终进入站点的是少量可独立阅读的 Markdown 和已确认可公开的图片。

## 来源优先级

1. 飞书默认“分享”目录：优先使用已经面向他人整理过的教程。
2. 飞书活动目录：用于整理分享文章和时间笔记，当前重点是 `0704分享`、`0718分享`。
3. `E:\workspace\article`：补充已经成稿或接近成稿的旧内容，不批量读取日报、周报和内部运行记录。
4. `eryuOS` 内容生产模块：优先使用已有公开稿、分享稿和资产边界说明。
5. `eryuOS-assets` / OSS：只取文章需要的图片和演示资产，不把私有 OSS 地址直接写进网页。
6. 旧 GitHub Pages：仅用于找回历史事实和选题，不直接复制生成后的 Hexo HTML。

## 内容整理流程

每篇内容按以下步骤进入站点：

1. 发现来源：记录飞书标题、本地文件或 `assets://` 逻辑 URI。
2. 先读目录：只读取标题结构，判断是否值得继续。
3. 公开边界扫描：检查账号、凭据、私人地址、客户信息、未公开结果和讲者备注。
4. 内容定位：确定它是文章、时间笔记、作品集证据，还是仅保留为私有来源。
5. 去重：检查是否与站内已有文章表达同一观点；重复时优先扩写已有文章。
6. 重写：按当前语气整理，不直接复制飞书讲义、口播稿或旧博客 HTML。
7. 资产选择：只复制正文真正使用的图片，确认脱敏、授权和尺寸。
8. 本地预览：检查标题、摘要、移动端、图片、代码块和链接。
9. 发布 Gate：`draft: false` 前确认事实、公开边界和可独立阅读性。
10. 构建部署：运行测试、Astro 检查和构建，再发布 `dist/`。

## Markdown 与元数据

第一阶段继续沿用现有 Astro Content Collections，不引入 CMS，也不增加数据库。

现有字段足够完成首批内容：

```yaml
title: "文章标题"
description: "列表页摘要"
date: 2026-07-17
category: "Agent 工作流"
draft: true
featured: false
```

只有真实需求出现时再增加字段。优先考虑的扩展是：

- `updated`：文章有明确更新日期时使用。
- `cover`：确实有文章封面时使用。
- `tags`：文章数量足够、需要跨分类检索时使用。

来源记录不直接进入公开 frontmatter。私有来源映射放在迁移清单或 `eryuOS`，避免站点仓库未来调整可见性时泄露飞书入口和内部路径。

## 图片与 OSS

- `assets://` 是私有资产逻辑地址，不能直接作为网页 URL。
- OSS 继续保持私有源资产库角色，不让浏览器直接依赖长期签名 URL。
- 文章确定发布后，把选中的公开图片复制到站点 `src/assets/articles/<slug>/`。
- 需要原样下载的附件才放 `public/`；普通正文图片优先交给 Astro Image 处理。
- 每篇首批文章建议 0 到 3 张图片，避免把分享稿变成截图堆砌。
- 图片进入站点前检查人物授权、账号信息、二维码、域名、路径、通知栏和浏览器标签。

当前可直接继续评估的资产：

- 2026-06-13 南京 AI 实践圈分享的公开流程图和封面图。
- 截图隐私打码器的公开 HTML 演示资产。
- 2026-05-31 WayToAGI 分享中的少量核心图，不迁移 800MB 级导出目录。
- HyperFrames 可视化说明，后续用于视频工作流文章，不进入首批。

## GitHub 与部署

- 当前项目目录尚未初始化 Git。
- 新建一个私有 GitHub 仓库保存 Astro 源码、Markdown 和已确认公开的小型图片。
- `sealofyou/sealofyou.github.io` 保持历史归档，不作为当前主页源码。
- VPS2 只保存构建产物，不在线上直接编辑 Markdown 或源代码。
- 第一阶段可以本地构建后部署；仓库稳定后再增加 GitHub Actions 自动构建和发布。
- 线上回滚以构建产物版本或 Git 提交为依据，不把 VPS 上的临时修改当作事实源。

## 暂不需要用户补的数据

当前不要求一次性补齐文章全文、活动图片、合作文案或所有项目资料。第一阶段只需要在具体文章进入发布前确认：

- 这篇是否允许公开。
- 文中出现的截图和结果是否允许公开。
- 是否有必须删除或模糊处理的个人、活动或平台信息。

其余内容可以随着新项目、新分享和新判断逐步增加。

## 验收清单

- 首批内容能说明真实 AI 工作流，而不是工具列表。
- 文章和时间笔记分工明确，没有同一份内容复制两遍。
- 没有讲师备忘、私有路径、账号凭据、订阅地址或未确认结果。
- 没有为了填满主页迁移算法题解、日报或古早博客。
- 图片来自可追溯来源，公开边界已确认。
- 线上内容完全来自当前 Astro 仓库的构建产物。
