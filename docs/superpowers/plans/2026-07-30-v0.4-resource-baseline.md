# V0.4 首屏资源基线与优化结果

## 目标

在不修改桌面构图、坐标、材质、文案和交互的前提下，减少首页首次访问的无效图片下载，并为后续 GLB 模型建立资源预算检查。

开发工作树：`E:\workspace\Projects\ai-wan-eryu-homepage-v0.4`

开发分支：`codex/v0.4-resource-baseline`

## 修改前基线

在生产构建和正常 WebGL 环境中，首页会请求：

| 资源 | 字节 | 是否必需 |
| --- | ---: | --- |
| `fallback-composition.png` | 2,141,964 | 否，仅 WebGL 失败时需要 |
| `main-avatar.png` | 2,191,104 | 是 |
| `q-avatar.png` | 1,902,688 | 是 |
| 首页 JS 入口 | 571,064 | 是 |

三张图片合计 `6,235,756` 字节。降级图虽然位于带有 `hidden` 的容器内，但 HTML 中存在真实 `src`，浏览器仍会立即下载。

## 实现

1. 降级图改为 `data-src`，只在 Three.js renderer 初始化失败时设置真实 `src`。
2. 主屏人物图改为 `main-avatar.webp`，保留原 PNG 作为加载失败回退。
3. Q 版摆件图改为 `q-avatar.webp`，保留原 PNG 作为加载失败回退。
4. 两张 WebP 使用质量 `92`、Alpha 质量 `100` 生成。
5. 新增 `npm run optimize:desktop-assets`，可以从保留的 PNG 源文件重复生成 WebP。
6. 新增 `npm run check:assets`，检查人物图、降级图、首页 JS 和未来 GLB 文件体积。

## 修改后结果

正常 WebGL 首屏请求：

| 资源 | 字节 |
| --- | ---: |
| `main-avatar.webp` | 230,910 |
| `q-avatar.webp` | 134,602 |
| 首页 JS 入口 | 571,339 |

首屏人物图合计从 `6,235,756` 字节降为 `365,512` 字节，减少 `5,870,244` 字节，图片负载下降 `94.14%`。

将首页 JS 一并计算，相关首屏负载从 `6,806,820` 字节降为 `936,851` 字节，下降 `86.24%`。CSS、HTML 和小型图标未计入这组对比。

正常 WebGL 网络请求中不再出现 `fallback-composition.png`。模拟 WebGL 初始化失败时，页面会请求该图片并正常显示降级说明，同时不会请求两张桌面人物图。

## 视觉验证

在同一个 Chromium 和 `prefers-reduced-motion: reduce` 环境中，将 WebP 页面与强制使用原 PNG 的控制页截图对比：

| 视口 | 最大单通道差 | 单通道差超过 5 的像素 | 平均单通道差 |
| --- | ---: | ---: | ---: |
| `1440x900` | 5 | 0 | 0.0108 |
| `1920x1080` | 5 | 0 | 0.0169 |

该差异只来自图片编码，不改变布局、裁切比例或场景结构。

## 最终验证

- `47` 个 Vitest 测试全部通过。
- Astro check：`0 errors / 0 warnings / 0 hints`。
- 生产构建通过，生成 `6` 个静态页面。
- `npm run check:assets` 全部预算通过。
- `1440x900` 和 `1920x1080` 均正常加载一个 WebGL Canvas，控制台无错误。
- 左侧屏幕切换、鼠标位置、键盘位置和鼠标垫模式状态更新正常。
- 触发 `pagehide` 后 Canvas 从 `1` 变为 `0`，调试 API 被移除。
- 模拟 WebGL 初始化失败时，降级图成功按需加载并显示。

## 资源预算

- 主屏人物图：不超过 `250 KB`
- Q 版摆件图：不超过 `150 KB`
- 两张首屏人物图合计：不超过 `400 KB`
- WebGL 降级构图图：不超过 `2.2 MB`，且不得正常首屏请求
- 首页 JS 入口：不超过 `650 KB`
- 后续每个桌面 GLB：不超过 `3 MB`

## 本阶段不做

- 不拆分 Three.js JS chunk。
- 不接入 GLB 模型。
- 不修改默认鼠标、键盘或其他桌面物件。
- 不实现手机版。
- 不部署公网。
