# img2threejs 物件代码接入秒哒设计

## 背景与纠正

秒哒参赛版第一次生成已经证明副屏切换、便利贴和实体鼠标拖动等交互可以成立，但视觉结果把机箱、鼠标、键盘、台灯和人物摆件简化成了低精度 CSS 几何占位。这不是后续要继续打磨的视觉基线。

此前把 img2threejs 仅理解为“拆件和分轮验收的方法”是不完整的。真正要复用的是它为单个参考物件生成的可编辑 Three.js / TypeScript 工厂代码。经过独立渲染和视觉验收后，这些代码作为参赛版的模型资产进入秒哒项目；秒哒负责装配场景、内容和交互，不再自行猜测设备外形。

## 目标

建立一条可重复的物件生产链：

```text
真实物件照片
  -> img2threejs 分析、规格与分阶段建模
  -> 独立 Three.js 渲染与参考图对照
  -> 统一物件工厂接口
  -> 秒哒原生 Three.js 场景装配
  -> 交互与性能验收
```

首个试验对象是有线 Logitech G502 游戏鼠标。试验通过后，再依次处理键盘、机箱、台灯和 Q 版摆件。整张桌面不会作为单个模型交给 img2threejs 重建。

## 三层职责

### 1. 物件生成层

img2threejs 只负责可观察的实体外观：轮廓、分块外壳、按键、滚轮、侧翼、接缝、材质和可命名的附件节点。

每个物件输出独立的 TypeScript 工厂，核心结果是一个局部坐标下的 `THREE.Group`。生成物不得包含页面路由、屏幕文案、桌面世界坐标或秒哒业务状态。

### 2. 适配层

适配层把生成的 `THREE.Group` 包装成项目已经使用的 `SceneObjectResult`：

```ts
interface SceneObjectResult {
  group: THREE.Group;
  interactiveTargets?: THREE.Object3D[];
  update?: (state: DesktopState) => void;
  dispose?: () => void;
}
```

适配层负责：

- 把模型缩放到桌面世界尺寸。
- 设置初始旋转、阴影和品牌贴图。
- 建立简单、稳定、透明的交互代理，不直接用复杂模型网格做拖动命中。
- 在页面卸载时释放几何体、材质和纹理。
- 保持生成模型与交互代码彼此可替换。

### 3. 秒哒场景层

秒哒项目使用固定相机的实时 Three.js 场景呈现“2.5D 构图”：对象是真实三维物件，但访问者不能自由绕场景旋转相机。主屏内容、副屏入口、便利贴和徽章继续由 CanvasTexture、纹理或独立交互面承载。

秒哒场景层负责：

- 房间、桌面、主副屏、洞洞板等基础空间结构。
- 物件的位置、旋转、缩放和前后遮挡关系。
- 副屏切换主屏、实体鼠标拖动、主屏光标映射和点击彩蛋。
- 响应不同横屏分辨率，但本阶段不实现手机竖屏布局。

## G502 首个物件

### 输入

- 主参考图：`reference/mouse-logitech-g502-primary-v1.jpg`
- 物件身份：有线 Logitech G502 游戏鼠标。
- 官方比例基线：长 `131.2 mm`、宽 `75 mm`、高 `40 mm`。
- 页面风格：保留真实 G502 轮廓和部件关系，处理成干净的新机状态。

### 必须保留

- 右手人体工学的不对称轮廓。
- 分离的左右主键和中央脊线。
- 金属或深灰滚轮及其凹槽。
- 滚轮后方的模式键与 DPI 按键。
- 左侧拇指托、侧键区域和锐利但有倒角的分块外壳。
- 前端线缆出口。

### 必须改变或忽略

- 不还原灰尘、磨损和污渍。
- 不在模型上保留 Logitech `G` 标志；该区域改为尔玉 `E` 标志。
- 不添加参考图中看不到的 RGB 灯带、额外按键或科幻纹路。
- 鼠标垫、桌面、数据线以外的背景物品不进入模型。

### 模型坐标与运行节点

- 模型局部原点位于鼠标底面中心。
- `Y` 轴向上；鼠标前端朝局部 `-Z`；右侧为局部 `+X`。
- 输出整体归一化到真实长宽高比例，世界尺寸由适配层统一缩放。
- 命名节点至少包含 `body`、`leftButton`、`rightButton`、`wheel`、`sideShell`、`logoMount` 和 `cableSocket`。
- `cableSocket` 只提供线缆连接位置；线缆曲线不固化在鼠标模型里。

### 线缆与拖动

鼠标本体沿用现有桌垫范围拖动逻辑。线缆由场景层使用曲线或 `TubeGeometry` 连接 `cableSocket` 与固定桌面锚点，并在鼠标移动时更新。线缆不参与射线命中，也不能阻挡拖动。

首轮若动态线缆影响稳定性，可以保留接口并暂时隐藏线缆；不得因此把鼠标改成另一种无线造型。

## 生成与验收顺序

### 第一门：照片与规格

- 主体完整、可辨认，遮挡不影响轮廓判断。
- 物件身份、尺寸基线、保留细节和忽略项已明确。
- 单张图无法证明的底部和右侧隐藏结构只做保守对称或简化。

### 第二门：模型独立验收

按 img2threejs 的固定阶段执行：

1. `blockout`
2. `structural-pass`
3. `form-refinement`
4. `material-pass`
5. `surface-pass`
6. `lighting-pass`
7. `interaction-pass`
8. `optimization-pass`

每一阶段都必须保存实际渲染截图和参考图对照。视觉评分低于 `90` 时不得进入秒哒集成；修正模型规格或代码后重新验收。

### 第三门：秒哒集成验收

- 模型能在秒哒项目的 Three.js 版本中构建和运行。
- 鼠标拖动范围、主屏光标映射和点击代理与现有行为一致。
- 模型不会改变主屏大小、桌面构图和其他物件坐标。
- 页面卸载后资源释放，控制台无未处理异常。
- `1440x900` 与 `1920x1080` 均能维持批准构图。

## 代码与资产交付

生成物保存在公开主页项目中，不进入 eryuOS：

```text
modeling/img2threejs/mouse-g502/
├── assessment.json
├── object-sculpt-spec.json
├── mouse-g502.ts
├── adapter-notes.md
├── renders/
└── comparisons/
```

秒哒接入时只提供已经验收的模型源码、必要纹理和适配说明，不上传整个 Astro 工程、Git 历史、构建产物或环境文件。若自动文件上传受限，可把这些小型公开源码提交到当前 GitHub 仓库，再由秒哒读取固定提交的 raw URL；不能使用会随分支漂移的临时地址作为最终依赖。

## 比赛边界与风险

- 最终可运行项目仍在秒哒中创建、装配、修改和发布。
- img2threejs 输出按“专门为本项目生成的模型资产源码”处理，不把已有 Astro 页面整体迁入秒哒。
- 提交比赛前需要向赛事规则或主办方确认：由外部工具生成、再在秒哒中集成的模型源码是否符合“完全使用秒哒开发”的解释。
- 若主办方明确禁止此类源码资产，参赛版停止使用该路线；本地个人主页仍可继续使用生成物。

## 非目标

- 本轮不生成整套桌面。
- 不替换线上 `eryu.fun`。
- 不发布秒哒 V1 几何占位版。
- 不同时处理键盘、机箱和台灯。
- 不为了展示 3D 技术增加自由相机、轨道控制器或大幅自动旋转。
