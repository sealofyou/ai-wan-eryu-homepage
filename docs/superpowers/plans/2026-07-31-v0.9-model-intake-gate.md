# V0.9 真实物件模型接入 Gate

## 目标

在没有真实物件照片时，不猜测键盘、机箱或台灯的外观，也不改动已经验收的桌面。先把照片输入、模型来源、授权、体积、坐标、回退和验收要求做成可执行的资产 Gate。

下一次收到照片后，每轮只处理一个物件：

1. 原始照片先做隐私检查，不默认进入公开仓库。
2. 同一组照片可以生成多个候选，但候选不能直接覆盖当前程序化物件。
3. 候选 GLB 通过清理、资产清单、体积和构建检查后，才获得显式预览入口。
4. 用户验收后才能改变默认视觉；程序化物件永久保留为回退。

## 本阶段范围

新增：

- 桌面模型资产清单，记录文件、对象、来源、授权、生成工具、输入素材权利、坐标、原点、预算和默认状态。
- 模型资产检查脚本及 TDD 回归测试。
- 真实物件拍摄与隐私处理说明。
- 一条真实 Build in Public 更新，说明本阶段做了什么。

不新增：

- 新的 GLB 候选。
- 键盘、机箱、台灯等默认模型切换。
- 外部图片转 3D API 调用。
- 页面可见控制面板。
- 手机版或公网部署。

## 资产清单规则

每个公开模型必须声明：

- 唯一 `id` 和所属 `object`
- 仓库内 `.glb` 文件名
- 来源类型、生成工具和生成日期
- 输入素材权利与模型授权说明
- Y 轴向上、正面朝向和原点约定
- 单位与场景缩放
- 文件体积预算
- 是否默认启用
- 可选的显式预览查询参数

Gate 必须拒绝：

- 缺失或大小写不一致的文件
- 跳出模型目录的路径
- symlink 或 junction
- 重复 id
- 缺少来源、授权或输入权利说明
- 非 GLB 文件
- 超过声明预算或仓库上限的文件
- 默认启用但没有经过用户验收的候选

## TDD 顺序

1. 先写失败测试，覆盖合法清单和上述拒绝条件。
2. 实现最小检查器，让测试转绿。
3. 为现有 `gaming-mouse.glb` 建立首条完整记录。
4. 将 `check:models` 接入 `verify:release`。
5. 更新拍摄说明与 Build in Public 时间线。
6. 跑全量测试、Astro check、build、资源 Gate、发布 Gate。
7. 在真实浏览器确认默认首页没有 GLB 请求、视觉与 V0.8 基线一致。

## 验收与回退

- 默认桌面视觉、文案、坐标和交互必须保持不变。
- 默认首页仍不得预加载 GLB。
- 模型 Gate 与发布 Gate 都通过。
- 本阶段在独立工作树提交并推送，验证后再合入 `master/main`。
- 合并后建立独立标签；公网仍不更新。
