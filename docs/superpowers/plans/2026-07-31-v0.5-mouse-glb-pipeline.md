# V0.5 鼠标 GLB 管线实施计划

## 目标

在不改变已验收桌面默认视觉、构图和交互的前提下，用一只鼠标跑通从可重复生成的模型资产到 Three.js 场景的完整 GLB 链路。

本阶段只提供内部试验入口。默认页面继续使用当前程序化鼠标；GLB 加载、解析或释放失败时也必须自动保留程序化鼠标。

## Git 与发布边界

- 基线提交：`68d0132`
- 恢复标签：`homepage-v0.4-accepted-20260731`
- 工作树：`E:\workspace\Projects\ai-wan-eryu-homepage-v0.5`
- 分支：`codex/v0.5-mouse-glb`
- 不部署公网，不修改手机版，不默认替换当前鼠标。

## TDD 顺序

1. 先为模型模式解析、单次下载缓存、失败回退、幂等释放和资源预算写失败测试。
2. 实现独立的 GLB 资产存储，负责下载、解析、缓存引用和释放。
3. 将鼠标拆成稳定交互容器和可替换视觉层，保持拖拽、主屏光标同步及点击代理不变。
4. 用 URL 查询参数 `?mouse=glb` 开启内部试验；无参数时保持程序化版本。
5. 增加可重复生成的游戏鼠标 GLB 脚本、资产说明和工具对照。
6. 在真实浏览器中分别验证默认、GLB、GLB 加载失败和页面卸载四条路径。

## 资产与运行预算

- 单个 GLB 不超过 `3 MB`，本轮目标控制在 `500 KB` 内。
- 鼠标模型使用独立交互代理，不使用复杂网格直接参与射线命中。
- 默认首屏不得请求 GLB。
- GLB 试验版不得改变鼠标的移动边界、拖拽状态和主屏光标映射。
- 页面卸载后，GLB 的几何体、材质和纹理必须释放。

## 验收 Gate

- 默认地址与 V0.4 视觉一致，网络请求中没有 GLB。
- `?mouse=glb` 能加载候选模型并保持全部鼠标交互。
- 模型地址无效时自动显示程序化鼠标，页面无未处理异常。
- 全量测试、Astro check、生产构建和资源预算检查通过。
- 生成默认版与 GLB 试验版双分辨率截图，并保留本地预览地址。

## 本阶段明确不做

- 不替换键盘、机箱、台灯或 Q 版摆件。
- 不把外部生成工具未经清理的模型直接放入正式页面。
- 不公开 API key、服务凭据、私有路径或未确认的授权信息。
- 不合并默认视觉替换，也不部署到 `eryu.fun`。

## 实施结果

- 新增按字节下载缓存的 GLB 资产存储；并发实例共享一次下载，解析后各自持有可幂等释放的模型。
- `GLTFLoader` 使用动态导入，默认页面不会下载模型文件或模型加载器。
- 鼠标由稳定交互容器、程序化视觉层、GLB 视觉层和简化命中代理组成。
- 模型加载或解析失败时保留程序化鼠标，不产生未处理异常。
- 场景统一登记 `SceneObjectResult`，点击只射线检测明确的 `interactiveTargets`，卸载前调用物件自己的 `dispose()`。
- 自建游戏鼠标 GLB 可由 `npm run generate:mouse-model` 重复生成，最终体积 `435,088` 字节。
- 模型经过三轮截图检查：第一轮 `58` 分、第二轮 `84` 分、第三轮 `91` 分；默认视觉没有被替换。

## 浏览器验证

- 默认地址在 `1440x900`、`1920x1080` 下与 V0.4 对应截图均为 `0` 像素差。
- 默认地址没有 GLB 请求，控制台没有错误。
- `?mouse=glb` 只请求一份 `gaming-mouse.glb`，模型状态切换为 `glb`。
- 真实点击左侧副屏后，主屏进入文章列表。
- 真实拖动 GLB 鼠标后，物理位置与主屏光标同步更新。
- 键盘拖拽和鼠标垫画笔模式保持正常。
- 注入损坏 GLB 后自动回退为 `procedural`，没有控制台错误或页面异常。
- 触发 `pagehide` 后 Canvas 从 `1` 变为 `0`，调试 API 与模型状态标记被移除。
