# AI玩尔玉个人主页 V0.8 发布候选计划

## 基线与目标

- 基线提交：`0854200`
- 基线标签：`homepage-v0.7-build-in-public-20260731`
- 开发分支：`codex/v0.8-release-candidate`
- 目标：把当前桌面版整理成可重复验证的本地发布候选，不改变已验收视觉。

V0.8 不增加新文章，不虚构内容，不默认启用 GLB 模型，不实现手机版，也不部署公网。

## 实现范围

1. 为构建产物增加发布候选检查器。
2. 检查首页、笔记、作品集和 Build in Public 项目页是否实际生成。
3. 检查构建后的站内链接和静态资源是否存在。
4. 检查构建产物是否泄漏本机绝对路径、凭据形态或本地开发地址。
5. 检查新窗口外链是否带有 `noopener noreferrer`。
6. 增加一条可重复执行的完整验证命令。
7. 在常见横屏尺寸下检查非空渲染、溢出、控制台错误、交互和资源释放。

## TDD 顺序

1. 先为有效构建、断链、敏感内容和不安全外链建立失败测试。
2. 实现纯函数检查器，使测试转绿。
3. 接入真实 `dist` 检查命令。
4. 运行单测、Astro check、生产构建、资源预算和发布候选检查。
5. 用真实 Chrome 完成多尺寸与交互验收。
6. 独立代码审查通过后再提交和合并。

## 验收 Gate

- 默认首页与 V0.7 在 `1440×900` 和 `1920×1080` 下保持 `0` 像素差。
- `1280×720`、`1366×768`、`1600×900`、`1920×1080` 和 `2560×1440` 均有可见 Canvas，且无横向溢出。
- “最近在做 → 项目预览 → 查看项目”链路可用。
- 构建产物无断开的站内链接、无本机路径和凭据形态。
- 单元测试、Astro check、build、资源预算与独立审查全部通过。

## 可逆性

- 所有修改只进入独立工作树和功能分支。
- 程序化物件和 V0.7 内容结构不删除。
- 合并前保留功能分支；合并后建立 V0.8 标签。
- 公网版本不更新，线上发布仍需单独验收。
