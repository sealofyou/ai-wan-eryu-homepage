# AI玩尔玉个人主页架构重构与 Build in Public 设计

## 目标

保留当前已经确认的三维桌面构图和交互，把项目整理成一套可以持续增加物件、替换模型、发布活动和记录开发过程的个人主页系统。

本阶段不实现手机版。手机版未来采用独立的“手机桌面 + App”交互，并与桌面版共享内容数据。

## 已确认决策

- 当前线上版本 `3aec85b` 是后续开发基线。
- Git 标签 `homepage-desktop-baseline-20260729` 保存重构前版本。
- 重构在 `codex/scene-modularization` 分支进行，不直接修改线上分支。
- 第一阶段严格零视觉变化：不改构图、坐标、材质、文案和交互。
- 采用分层场景工具箱方案，不引入 ECS、事件总线或物件插件框架。
- 未经本地测试、桌面截图复核和用户确认，不部署到公网。

## 一、代码主线

当前部署代码来自 `codex/keyboard-detail-pass`，旧的 `codex/public-homepage` 只保留为历史版本。后续应以当前生产代码树为主线，保留旧分支与提交，不通过强推删除历史。

两条无共同祖先的历史需要在单独维护步骤中统一：创建保留当前生产文件树的合并提交，使旧主线成为新历史的一部分，再把远程 `main` 更新到统一后的版本。场景重构可以先在当前生产基线分支上完成，但正式合并前必须完成主线统一。

`scene.ts` 只负责：

1. 读取页面节点和内容数据。
2. 创建 renderer、scene、camera、lights 和 world。
3. 调用物件工厂并加入场景。
4. 连接状态、屏幕绘制和交互控制器。
5. 启动、调整和销毁渲染循环。

### 物件接口

```ts
interface SceneObjectResult {
  group: THREE.Group;
  interactiveTargets?: THREE.Object3D[];
  update?: (state: DesktopState) => void;
  dispose?: () => void;
}
```

程序化模型和 GLB 模型使用相同结果结构。简单结构继续用 Three.js 几何体，复杂物件由 `assets.ts` 加载 GLB 后包装成 `SceneObjectResult`。

### 坐标规则

- 所有物件的位置、尺寸和旋转角度进入 `layout.ts`。
- 物件内部的局部坐标保留在对应物件模块中。
- 屏幕 Canvas 使用自身尺寸和比例常量，不读取世界坐标。
- 第一阶段只搬迁现有数值，不调整任何数值。

## 三、图片转 3D 与模型替换

采用混合建模，不把整个桌面交给图片转模型工具重新生成。

继续程序化建模：桌面、墙面、屏幕、鼠标垫、洞洞板基础结构和点击区域。

适合 GLB：键盘、鼠标、机箱、笔记本、台灯、人物摆件和具有明显外形特征的装饰品。

适合贴图或 decal：Logo、贴纸、徽章、屏幕内容和便利贴。

模型流程：

1. 收集正面、侧面、俯视和细节照片。
2. 使用 Tripo、Meshy、Hunyuan3D、Rodin 等工具生成候选模型。
3. 在 Blender 中修正比例、轴心、材质、法线、拓扑和多余几何。
4. 导出 GLB，并压缩网格和纹理。
5. 通过 `assets.ts` 加载，在对应物件模块中设置比例和交互代理。
6. 检查加载体积、阴影、点击区域、构图和帧率。

首个验证对象只选择键盘或鼠标。普通物件建议控制在 2–8 万三角面，单个 GLB 尽量控制在 1–3 MB，纹理以 1K 为主。图片转模型只提供初稿，不把未经清理的模型直接放到线上。

## 四、Build in Public

使用“个人主页实现”作为当前公开项目名。黑客松正式名称在从现有资料确认后补入标题和背景，不影响内容结构。

飞书公开目录：

```text
分享与活动
└─ 个人主页实现｜Build in Public
   ├─ 项目总览
   ├─ 为什么做这个个人主页
   ├─ 从普通页面到 3D 桌面
   ├─ 视觉方案与反复修改
   ├─ scene.ts 架构重构
   ├─ 图片转 3D 与模型替换实验
   ├─ 内容、活动与飞书接入
   ├─ 部署、测试与线上验证
   ├─ 失败记录与修改原因
   └─ 最终复盘
```

每次公开更新回答七个问题：做了什么、为什么做、修改前是什么、修改后是什么、遇到什么问题、证据在哪里、下一步是什么。

主页只增加一条 `type: project` 的“最近在做”内容，指向公开项目总页。详细更新保存在飞书，不把每天的日志全部塞进三维主屏。

未经确认的旧草稿不发布。“文章”入口在没有正式文章前隐藏，“最近在做”由个人主页实现项目填充。

## 五、公开复盘文档

最终形成《从一个想法到线上主页：我如何和 AI 一起实现可扩展的 3D 个人主页》。内容包括需求、视觉选择、失败方案、架构重构、模型接入、内容系统、部署验证、人和 AI 的分工，以及后续手机版方向。

- `eryuOS` 保存完整内部版本。
- 飞书知识库保存脱敏后的公开版本。
- API 密钥、服务器凭据、私有路径和未公开资料不进入公开版本。

## 六、架构重构后的体验修正

这些修改不与第一阶段结构重构混合：

- WebGL 失败时才加载 fallback 图片。
- 大尺寸头像转为优化后的 WebP 并使用带 hash 的资源地址。
- 暂时隐藏空的文章入口和没有内容的徽章入口。
- Build in Public 项目接入“最近在做”。
- 留言不显示弹窗；点击物理留言区域后，文字直接显示在便利贴上，Enter 确认，Esc 取消。
- 首期留言只保存在当前浏览器，不暗示已经发送给站主。

## 七、手机版边界

手机版本轮不实现。未来使用独立手机桌面：关于我、项目、分享与活动、文章和 Build in Public 以 App 图标呈现，点击后在手机内部打开页面。手机版不加载 Three.js，但与电脑版共享内容集合和公开链接。

## 验收与发布 Gate

- 重构前后的桌面截图在 `1440×900`、`1920×1080` 下无明显构图变化。
- 鼠标、键盘、屏幕、洞洞板、便签、徽章、鼠标垫和留言模式行为保持一致。
- 全量测试、Astro check 和构建通过。
- 新增一个临时测试物件只需要物件模块、layout 配置和装配入口；验证后删除。
- 所有改变先提交到重构分支。
- 用户本地验收页面后，才允许合并和部署。

## 执行顺序

1. 固定 Git 基线并创建重构分支。
2. 写入设计与实施计划。
3. 锁定源代码结构、状态逻辑和桌面截图。
4. 抽离 Canvas 工具和屏幕绘制。
5. 抽离渲染核心、资源和动作注册。
6. 按物理区域抽离物件。
7. 抽离拖动、鼠标垫和留言交互。
8. 完成全量回归并由用户本地验收。
9. 体验修正、Build in Public 和 GLB 试验分别进入后续批次。
