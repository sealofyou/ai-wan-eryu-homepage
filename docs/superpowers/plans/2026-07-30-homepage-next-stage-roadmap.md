## 已确认边界

1. 先完善电脑版，不实现手机版。
2. 不重新生成整套桌面，只对适合的复杂物件使用 GLB。
3. 程序化模型始终保留为回退方案，GLB 试验失败不能影响当前页面。
4. Build in Public 是真实项目记录，不补写虚构数据、成绩或合作信息。
5. GitHub 主分支合并不等于公网发布。公网更新必须经过单独验收。

### V0.4：资源与性能基线

目标：在增加 3D 模型前先建立体积和加载基线，避免新模型继续放大首屏负担。

工作项：

1. 记录当前 JS、图片、纹理和首屏请求体积。
2. WebGL 正常时不下载降级构图图，只在初始化失败后加载。
3. 检查头像和封面是否都使用构建后的 WebP，而不是直接下载原始 PNG。
4. 为后续 GLB 增加资源体积清单和构建检查。
5. 保持 `1440x900`、`1920x1080` 的默认页面截图不变。

验收 Gate：

- 页面视觉和交互不变。
- 首屏不再无条件请求降级大图。
- 测试、Astro check 和 build 全部通过。
- 形成修改前后的资源体积对照表。

### V0.5：GLB 模型管线验证

目标：先用一个小物件跑通图片/模型到 Three.js 的完整链路，不直接替换整套桌面。

首个对象选择鼠标。鼠标体积较小、交互边界清晰，适合验证模型加载、比例、轴心、阴影、点击代理和拖动同步。键盘作为第二个对象，不在首轮同时处理。

工作项：

1. 对 Tripo、Meshy、Hunyuan3D、Rodin 和可用的本地方案做一次工具对照，记录输入要求、导出格式、授权边界和清理成本。
2. 在 `public/models/desktop/` 建立模型目录与资产说明。
3. 在 `src/desktop/core/assets.ts` 增加 GLB 加载、缓存、错误处理和释放入口。
4. 为鼠标物件增加“程序化模型 / GLB 模型”双实现，默认仍使用当前程序化模型。
5. 使用开发参数或内部配置切换 GLB，不增加破坏桌面观感的页面控制面板。
6. 在 Blender 中统一比例、轴心、法线、材质和纹理后再进入项目。

模型预算：

- 普通单物件建议 `2-8` 万三角面。
- 单个 GLB 尽量控制在 `1-3 MB`。
- 纹理以 `1K` 为主，只有确实需要近距离查看时才提高。
- 必须保留简化点击代理，不直接把复杂网格当交互碰撞体。

验收 Gate：

- GLB 加载失败时自动回退到当前鼠标。
- 鼠标拖动、主屏光标同步和边界限制保持正常。
- 没有内存泄漏，页面卸载后模型资源被释放。
- 提供默认版与 GLB 试验版截图，由用户决定是否替换。

### V0.6：桌面物件逐个升级

目标：在鼠标管线通过后，每次只替换一个物件。

建议顺序：

1. 键盘。
2. 机箱。
3. 台灯。
4. Q 版人物摆件。
5. 后续新增的笔记本或个性化装饰。

每个物件单独提交、单独截图、单独验收。桌面、墙面、显示器、鼠标垫、洞洞板基础结构和交互区域继续使用程序化建模。

### V0.7：Build in Public 内容接入

目标：让“最近在做”真正承载个人主页实现过程，而不是只显示占位文案。

内容结构：

```text
个人主页实现｜Build in Public
├─ 项目总览与当前状态
├─ 为什么做这个主页
├─ 从普通页面到 3D 桌面
├─ 视觉方案与失败修改
├─ scene.ts 架构重构
├─ 图片转 3D 与模型替换实验
├─ 内容、活动与飞书接入
├─ 测试、部署与线上验证
└─ 阶段复盘
```

实现方式：

1. 仓库 Markdown 保存结构化事实、时间线、阶段状态和公开链接，作为网站构建数据源。
2. 首页“最近在做”显示项目摘要、当前阶段和最近一条更新。
3. 点击详情后进入站内项目页，不在主屏里塞完整长文。
4. 飞书知识库保存适合阅读和分享的长文版本；站内项目页可以链接到对应飞书文档。
5. 网站不在运行时依赖飞书接口，避免未登录权限、网络和跨域问题。

首批可整理内容：

- 需求如何从普通个人主页变成可玩的 3D 桌面。
- 已确认构图和反复修改的原因。
- 两套代码主线分叉的诊断与合并方式。
- `scene.ts` 从 `1412` 行拆分到 `366` 行的过程。
- `45` 个测试、双分辨率零像素差和生命周期清理验证。

验收 Gate：

- “最近在做”不再是空入口。
- 项目详情能按时间阅读，但首页仍保持简洁。
- 所有内容均能追溯到真实提交、截图或现有文档。
- 不公开服务器凭据、API key、本地敏感路径或未确认信息。

### V0.8：整体验收与发布候选

目标：将通过验收的模型和 Build in Public 内容组合成一个可发布候选版本。

工作项：

1. 全量桌面交互回归。
2. `1440x900`、`1920x1080` 和其他常见横屏尺寸截图检查。
3. 首屏体积、帧率、WebGL 错误和资源释放检查。
4. 本地预览交给用户验收。
5. 验收后再合并主分支，部署仍作为独立操作执行。

当前实现补充：

- 一条 `verify:release` 命令串联测试、Astro 诊断、构建、资源预算和构建产物审计。
- 构建产物检查必需路由、HTML/CSS/srcset 引用、本机路径、回环地址、凭据形态和新窗口外链安全。
- 默认首页在两个基准分辨率下与 V0.7 保持零像素差，并覆盖另外四个常见横屏尺寸。
- Superpowers 文档继续作为计划和复盘载体，但不是网站运行依赖；实际实现以仓库测试、Git 工作树和发布 Gate 为准。

### V1.0：公网发布

只有 V0.8 本地验收通过后才执行：

1. 构建并备份当前线上版本。
2. 发布到目标服务器。
3. 验证 HTTP、HTTPS、静态资源、站内路由和外链。
4. 验证国内直连和异常回退。
5. 记录发布提交、部署时间和回滚方式。

### 后续独立项目：手机版

手机版不与以上桌面阶段混做。未来单独建立“手机桌面 + App 图标”方案，共享内容数据，但不加载 Three.js 桌面场景。

## 当前进度与接下来

`codex/v0.9-model-intake` 当前范围：

1. 保持默认 3D 桌面视觉和交互不变。
2. 为公开 GLB 建立机器可读的来源、授权、坐标、预算、预览和验收清单。
3. 把模型资产检查接入完整发布 Gate。
4. 固化真实物件拍摄角度、隐私边界和单物件替换流程。
5. 把本轮真实进展写回 Build in Public 时间线。
6. 通过独立代码审查后合入 `master/main`，推送远程并建立 V0.9 回退标签。

V0.9 合入后的顺序：

1. 等待用户提供某一个真实物件的完整照片与尺寸，优先从键盘开始。
2. 同一物件生成 2 至 3 个候选，清理后通过显式参数独立预览。
3. 用户确认候选后，才单独提交默认视觉切换；程序化版本永久保留。
4. 真实文章、活动和项目继续按现有 Markdown 内容模型逐条增加。
5. 公网部署与手机版仍分别作为后续独立步骤。
