# AI玩尔玉个人主页 Build in Public 设计

## 目标

把“个人主页实现”作为一个真实、持续更新的公开项目接入现有网站，让桌面端“最近在做”不再是空入口，同时保留已经验收的 3D 构图和默认交互。

这不是开发日志倾倒，也不是把完整文章塞进主屏。访客先在 3D 主屏看到一条项目摘要，再进入站内项目页阅读阶段记录和证据。

## 已确认边界

- 不修改默认桌面构图、相机、物件、材质和首页文案。
- 不实现手机版。
- 不部署公网；本地验收后再决定发布。
- 不编造比赛成绩、用户数据、合作案例或完成状态。
- 不公开 API key、服务器凭据、本地路径和未确认资料。
- 秒哒参赛版与 Astro 主站是并行实验，不把二者写成同一个实现。

## 方案选择

### 采用：项目总页 + 独立更新条目

- `projects` collection 保存稳定项目事实、当前阶段和站内入口。
- `projectUpdates` collection 每个文件保存一次阶段更新。
- `/projects/[id]/` 组合项目正文与按时间倒序的更新。
- 首页只把公开项目映射到桌面的 `recent` 栏目。

优点：

- 每次新增进展只增加一个 Markdown 文件，Git 历史天然可追踪。
- 项目稳定信息与阶段日志分开，避免一个超长 frontmatter 数组。
- 后续可以复用到其他 Build in Public 项目。
- 网站构建不依赖飞书 API 或运行时网络。

### 未采用：继续使用时间笔记的 `project` 类型

改动最少，但项目总览、当前状态和多次更新会混在一篇普通笔记中，后续难以复用，也会让“时间笔记”和“项目跟踪”再次混淆。

### 未采用：一个项目文件内维护更新数组

读取简单，但每次更新都要编辑同一大块 frontmatter，容易产生合并冲突，正文和结构化数据也会重复。

## 数据结构

### 项目

项目至少包含：

- 标题与一句话描述
- 开始时间、最近更新时间
- 当前状态和当前阶段
- 列表摘要与主屏预览
- 分类、是否推荐、是否公开
- 站内详情地址和可选的公开仓库地址

### 项目更新

每次更新至少包含：

- 所属项目 id
- 日期、阶段、更新类型
- 一句话摘要
- 1 至 4 条真实变化
- 可选的公开证据链接
- 正文中的判断、问题和下一步

证据链接只使用公开且稳定的 HTTP/HTTPS 地址。内部文档和本地路径可以作为整理来源，但不进入公开页面。

## 页面结构

项目页采用现有 `paper / ink / cold-green` 视觉语言，不制作新的营销落地页。

1. 项目标题、状态、当前阶段和更新时间。
2. 一段项目目的与当前边界。
3. 当前结果摘要，用数据行展示可核实变化。
4. 按时间倒序的 Build in Public 时间线。
5. 每条更新展示阶段、摘要、真实变化、正文和证据链接。
6. 末尾提供公开仓库入口；飞书长文只有在真实公开链接存在时才出现。

页面使用全宽分区和分隔线，不堆叠装饰卡片，不新增与 3D 桌面冲突的视觉风格。

## 首批真实记录

1. 从普通主页改为可玩的真实电脑桌面。
2. 两套代码主线分叉的诊断、统一与回退标签。
3. `scene.ts` 从 1412 行拆到 366 行，默认画面双分辨率零像素差。
4. 首屏图片从 6,235,756 字节降到 365,512 字节。
5. 鼠标 GLB 试验管线、程序化回退和默认零预加载。
6. 秒哒参赛版与 Astro 主站拆成两条实现线。

所有数字必须能在现有提交、测试结果或项目文档中找到依据。

## 桌面交互

- 左侧副屏仍然只有“文章 / 分享与活动 / 最近在做”三个入口。
- 点击“最近在做”后，主屏显示项目列表。
- 点击项目后，主屏显示项目摘要和当前阶段。
- 完整按钮文案为“查看项目”，在新标签页打开站内项目页。
- 没有项目时沿用现有空状态；本期至少接入一个真实项目。

## 测试与验收

- 先写失败测试锁定 collection、公开项目、更新排序和首页映射。
- 验证项目页只渲染公开项目及其公开更新。
- 验证项目站内地址能通过现有 URL 安全检查。
- 验证桌面预览按钮对 `recent` 显示“查看项目”。
- 运行 Vitest、Astro check、生产构建和资源预算检查。
- 用真实浏览器验证“最近在做 → 项目预览 → 项目页”完整链路。
- 在 1440×900 和 1920×1080 下复核默认桌面没有视觉变化。
